# vizqueryearth design

**Status:** the web app, built in October 2026; it runs on queryearth 0.7. It replaces version 1, a Jupyter editor on ipyleaflet, which is in the git history.

## 1. Goal

A page where anyone can see queryearth rules on a globe, check which of them apply to their own work, and write or edit rules without typing coordinates. The people who use it are the people who use the rules: they open a page, draw where they work, and read what applies. The people who keep a set of rules edit them on the same page and publish the result.

## 2. Decisions

**Browser-only.** By decision of the project, there is no server, no sign-in and nothing stored by us. A rules file is opened from disk or from a link (`?src=<url>`) and saved by downloading it. Unsaved edits are kept in the browser's storage as a safety net and offered back on the next visit; they are never the only copy we rely on.

**queryearth runs in the page.** Pyodide runs queryearth itself, from PyPI, and this repository's Python (`vizqueryearth/`). Every shape, edit, file and query goes through queryearth: files are read with `Registry.from_file` and written with `Registry.to_file`, and every edit is checked by adding every rule to a Registry before it is kept, so the rules the page holds are always ones queryearth reads, and the page can never save a file that queryearth would refuse or read differently. There is no second implementation of its rules in JavaScript. The JavaScript draws and wires events; `Session.call(name, json)` is its only way into Python, and also reads what people type (axis bounds such as `<8`). The same Python is tested in CI without a browser. The cost is the first visit: about 20 MB, cached afterwards.

**Hosting.** GitHub Pages, deployed from `main` by `.github/workflows/pages.yml`, which copies `web/` with the `web/py` symlink followed. GitHub Pages sends `Access-Control-Allow-Origin: *`, which pages hosted elsewhere need to load the app.

**Curated pages by pull request.** A page for a set of rules is a folder `web/sites/<name>/` with an `index.html` stub, `site.json` (title, description, rules, optional dimensions and view) and the rules file. Review of the pull request is the only moderation, and the page lives at `/sites/<name>/`.

**Self-hosting.** "Download as web page" gives one `index.html` that embeds the settings and the rules and loads `app.js` and `app.css` from wherever the app is hosted. It can go on any static host, or be opened from disk, with nothing of ours involved beyond the app's files.

**Files are queryearth's.** A rules file is written as queryearth 0.7 writes one: a `"queryearth"` member and the features, as indented JSON with each list of numbers on one line. Rules not edited keep every value as read. A 0.7 file does not declare its dimensions, so the page infers them from the rules' values: a range of `gt`, `ge`, `lt` and `le`, with an optional `unit`, makes an axis, and a name or a list of names makes labels. A site's `dimensions` come first, so a site can declare one no rule uses yet, or an axis's unit; the Dimensions panel shows them and lets an editor set a unit, add one or remove one no rule uses, and a downloaded web page embeds them. When the page writes an axis value it adds the axis's unit, so the file keeps it. A file that needs a later queryearth is refused with queryearth's own message, and the open file stays as it was.

**Older files open where they map.** Links to files written for queryearth 0.6 or before should still open, so `upgrade` converts what maps one to one: a code whose prefix was a declared category ("groups" before 0.6) takes the category's path, the declared labels and axis dimensions become the page's, a record `box` becomes the geometry, and a rule with changes and no level, which was info, says so. Everything else, such as an edge rule, recurrence or a withdrawn rule, is left for queryearth 0.7 to refuse, naming the rule; the page does not guess what the author meant. Category titles have no place in 0.7 and are dropped.

**Categories, in one tree.** A rule's code may be a path, such as `REGION/ITF/ITF001`, and its category is the path before the last slash (queryearth's `rule.category`). The rules are one outline built from the codes: All rules, the categories and subcategories, and the rules as leaves, sorted by name; a rule without a slash sits at the root. It is an ARIA tree that works from the keyboard. Picking a category shows everything under it on the globe; the text filter shows matching rules with their categories opened. Categories start closed, so a long file opens as a short list; each viewer's opened branches and filter are kept in browser storage, and a rule picked on the globe or in the results opens its categories. Managing happens in the same tree in Edit, one line to a row: drag and drop by a handle with pointer events, and, for phones and the keyboard, a Category select in a rule's form and Move to… in a category's ⋯ panel, which also renames, removes and adds categories. Since a category is only a path, moving a rule changes its code's path and keeps its last part, and renaming or moving a category rewrites every code under it; queryearth refuses a move that would give two rules one code, and the page refuses moving a category into itself. A new rule is numbered after the last part of its category's path. A category with no rule exists only in the page until a rule is put in it.

**Two modes on one page.** Check is for people who read the rules: check an area, filter the list, and open a rule's read-only card. Edit is for people who write them: the rule form, adding and moving rules, categories, dimensions, downloads and drawing rule shapes. They are one page with a switch rather than two pages, so a file, its filter and the globe stay as they are when switching; switching cancels a drawing, and the area being checked is kept but shown only in Check. `#check` or `#edit` in the address chooses the mode, so a link can say which; otherwise the main page opens in the viewer's last mode (browser storage) and a site's page or a downloaded page opens in Check, since most of their visitors read. Unsaved edits are offered back in Edit, which the page switches to unless the address asked for Check (a notice then points to Edit), so a draft is not missed. In either mode, selecting a rule, from the tree, its label or its shape, opens it in place in the tree. There are no browser dialogs: `prompt()` and `confirm()` return nothing in some embedded browsers, so titles, links and deletion use fields and a second click.

**Records to copy.** People copy a rule's GeoJSON to paste into another file, a gist or a message, so the rule form shows the record, and the card and each result copy it. The text comes from Python (`Rule.to_feature()`, and `Registry.to_file` for the whole file), never JSON the page builds itself. Where the clipboard is not allowed, the text is selected for Ctrl+C instead.

**Properties are shown and kept.** A rule carries properties beyond its code, title, message, level and scope, such as an instruction, references and evidence quotes. queryearth keeps them as given; the card shows the instruction, references and evidence in their own sections and every other property as it is, and edits never touch them.

**Read-only cards link out safely.** References and evidence come from rule files, which anyone can write, so only `http` and `https` addresses become links, opened in a new tab without access to the page.

## 3. Globe and drawing

**MapLibre GL's globe with Terra Draw.** Leaflet, used by version 1, draws Web Mercator, which stops near 85° and cannot show the poles; polar caps and Arctic or Antarctic rules are common for ocean and ice models. On a globe the poles and the date line are ordinary places.

**Longitudes are wrapped.** Terra Draw rejects longitudes beyond ±180, so drawings arrive between -180 and 180, and a shape across the date line has an edge that jumps, such as from 170 to -170. queryearth takes every edge the short way round and splits the shape at ±180, so a drawn polygon goes to queryearth as it is. A rectangle follows the same rule: corners at 170 and -170 make a shape 20° wide across the date line. Shapes that cross the date line, reach a pole or have holes cannot be handed back to Terra Draw to move their corners; they are redrawn instead.

**The poles.** MapLibre's globe draws map data only to about 85° and fills the rest from polygon edges that reach the pole. Rule shapes reach it exactly (a point drawn within 0.5° of a pole is taken to the pole), so a box to the pole, such as the Arctic cap the rule form offers, is filled to it. Land is Natural Earth's GeoJSON, which is cut at ±180; the world-atlas TopoJSON is stitched across ±180 and draws a band across the globe. Natural Earth's Antarctica runs to the pole along 89.99°S, which the globe draws badly, so it is cut at 84°S and a band of land from there to the pole replaces it. Rule labels on the far side of the globe are hidden.

**Turning to the rules.** Python gives the extent of the shapes, the short way round, so a set across the date line gets one extent. A page without a `view` opens on its rules, selecting a rule turns the globe to it, and a set that goes all the way round is shown from above its pole.

## 4. Follow-up

**Versioned app paths.** A downloaded page loads `app.js` from the site root, so it changes whenever the app does, and a breaking change to the settings it embeds would break it. The plan is to publish each major version of the app under its own path, such as `/v1/`, have downloaded pages point there, and keep the root for the latest. Not implemented yet.
